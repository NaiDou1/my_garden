# 重力方块：沙子 / 红沙 / 混凝土粉末 /铁砧/ 龙蛋
---

> 这五种方块都是 `FallingBlock` 的子类，采用「方块层 → 计划刻 → 下落实体」的三段式：

> 方块只负责**申请计划刻**并做一次性判断，真正的下落由实体 `FallingBlockEntity` 完成。

## 一、方块状态

四个方块都只有 1 个方块状态，**没有任何属性**（没有 `waterlogged`、没有 `age`），也都不参与随机刻：

| 方块                | 状态属性     | 计划刻延迟                     |
| ------------------- | ------------ | ------------------------------ |
| 沙子                | 无（单状态） | 2 gt                           |
| 红沙                | 无（单状态） | 2 gt                           |
| 混凝土粉末（16 色） | 无（单状态） | 2 gt                           |
| 龙蛋                | 无（单状态） | **5 gt**（唯一覆写延迟的方块） |

放置时的行为：

- 沙子 / 红沙：原样放置，不改变状态，放置后申请计划刻。
- 混凝土粉末：若放置位置的水满足固化条件（自身含水，或邻居有水且该面不是完整实心面），**直接以混凝土状态放置**；否则与普通重力方块相同。
- 龙蛋：原样放置，额外有 1 级亮度，不影响下落。

---

## 二、计划刻的添加条件

重力方块有两条添加计划刻的路径，**两条路径都不做任何条件判断**：

1. **被放置时**（`onPlace`）：无条件添加，延迟如上表所示。
2. **邻居形状变化时**（`updateShape`，即邻居变化引发的形状更新）：无条件添加，延迟如上表所示；不判断变化来自哪个方向，也不判断下方是否为空气。

因此「沙子被放在实心方块上」收到PP更新同样会产生一次计划刻，只是在执行时判定不通过、什么都不做。

补充规则：

- 优先级为默认 0（`NORMAL`）
- 同一（位置, 方块类型）已有未执行的计划刻时，新的调度被**直接丢弃**：既不会提前，也不会被推迟。
- 目标区块未加载时，该次调度被丢弃（不排队）。
- 延迟：沙子 / 红沙 / 混凝土粉末为 2 gt；龙蛋覆写为 5 gt。
- **混凝土粉末的两处例外**：
  - 放置遇水 → 直接变混凝土，不排计划刻、不生成实体；
  - 邻居变化时先判是否触水 → 触水则**当场**变混凝土（同一刻、不排计划刻）；未触水才走上面的通用调度。

---

## 三、执行计划刻时的逻辑

计划刻执行时：

1. 先校验该位置当前**仍是同种方块**；否则本次计划刻作废（中途被替换成别的方块时不执行）。
2. 判定是否开始下落：**正下方一格是「自由」方块**（空气 / 火 / 液体 / 可被替换的方块）**且**自身 Y ≥ 世界最低高度。
   - 不满足 → 什么都不做，且**不会自动重排**计划刻（之后能否下落取决于新的邻居更新）。
   - 满足 → 进入下一步。
3. 生成下落实体（`FallingBlockEntity.fall`），顺序为：
   1. 实体生成在方块中心（x+0.5, y, z+0.5），初始速度为 0，并记录起始位置；
   2. 若方块状态带 `WATERLOGGED`，**强制清除**该属性（下落实体一律不保留含水）；
   3. 原位置立即变为空气（或该处原本的流体）；
   4. 把实体加入世界。
> 第 3 步中「原位置变为空气」会触发邻居与形状更新，使**上方**的重力方块各自重新排入一次计划刻，因此一整柱沙子会以**每格 2 gt** 的速度逐格下落。

> 同一游戏刻内的顺序是「计划刻阶段 早于 实体运算阶段」，所以本次生成的下落实体**在同一刻就开始下落**。


---

## 四、下落实体每刻的判断顺序

实体生成后，每个游戏刻按固定顺序执行：

1. 方块状态为空 → 直接移除实体，本刻结束。
2. `time++`；施加重力（0.04 / gt）；按速度移动（移动过程会写入是否落地、是否发生碰撞）；应用方块效果与传送门。
3. **仅在服务端且实体存活时**做落地判定：
   1. 取当前所在方块位置；判断自身是否为混凝土粉末。
   2. 混凝土粉末：若当前位置是水 → 标记「浸水」；若速度平方 > 1，再从上一刻位置到当前位置做一次**液体裁剪**，命中水源则以命中位置为准（防止高速穿过水面未被识别）。
   3. **未落地且未浸水**：
      - 若 `time > 100` 且（低于世界最低高度或高于世界最高高度），或 `time > 600` → 移除实体，并在 `dropItem` 与游戏规则 `ENTITY_DROPS` **都允许**时掉落自身方块物品；
      - 否则继续下落。
   4. **已落地或浸水**：
      - 速度乘以 (0.7, -0.5, 0.7)；
      - 若脚下是**移动中的活塞** → 本刻不做任何处理，跳过落地逻辑；
      - 若 `cancelDrop` 为真（铁砧损坏一类）→ 移除实体并调用 `onBrokenAfterFall`；
      - 否则依次判断三个条件：
        - `mayReplace`：当前位置的方块可被替换；
        - `wouldContinueFalling`：下方仍自由，且（非混凝土 **或** 未浸水）；
        - `wouldSurvive`：方块状态能在该位置存活，且不满足 `wouldContinueFalling`；
        - 前两个条件都成立 → 需要时补回 `WATERLOGGED`，把方块放回、同步一次方块更新包、移除实体，并调用 `onLand`（**混凝土在此固化成混凝土**）；
        - 条件不成立或放回失败 → 移除实体，视规则掉落物品并调用 `onBrokenAfterFall`。
4. 最后乘以空气阻力 0.98；根据本刻是否发生碰撞，决定是否启用精确位置同步。

## 五、四个方块的响应流程

- **沙子 / 红沙（重力方块通用流程）**
  - 被放置 → 无条件排 2 gt 计划刻。
  - 邻居变化 → 无条件排 2 gt 计划刻。
  - 计划刻执行 → 下方自由且未到世界底部 → 原位变空气 + 生成下落实体；否则无动作。
  - 实体每刻 → 重力下落 → 落地后放回方块（落地后若下方又变自由则再次进入下落判定）；超时或无处放置则移除并可能掉落物品。
  - 沙 / 红沙的差异只在尘粒颜色与沙漠环境音，与下落无关。

- **混凝土粉末**
  - 被放置且位置/邻居有水 → 直接放成混凝土：无计划刻、无实体。
  - 被放置且无水 → 与沙子完全相同的 2 gt 计划刻流程。
  - 邻居变化且触水 → 立刻变混凝土（同一刻），不排计划刻。
  - 邻居变化未触水 → 排 2 gt 计划刻。
  - 计划刻执行 → 与沙子相同；生成实体后，若下落中或落地时检测到水（含高速穿水的裁剪检测）→ 视为「浸水」，不再继续下落，落地即固化为混凝土。

- **龙蛋**
  - 下落部分与沙子**完全一致**，唯一区别是计划刻延迟为 5 gt。
  - 右键或左键 → 仅在服务端，最多尝试 **1000 次**随机偏移（水平 ±16、垂直 ±8）；命中条件为「目标位置是空气、目标下方不是空气、在世界边界内、在建筑高度内」；命中则播放传送粒子并把自身瞬移到该位置（`setBlock` flags=2，不触发邻居更新；原位置直接移除且不掉落）；1000 次全部失败则**什么都不发生**。
  - 传送是瞬移、不是下落，它与下落逻辑互不影响。

---

## 六、判定顺序要点

- **调度阶段不判断，判断全部在计划刻执行时**：`onPlace` / `updateShape` 无条件排刻，`isFree(below) && Y ≥ 世界最低高度` 在刻内判定。
- **只判断正下方一格**；沙柱逐格下落是邻居更新连锁的结果。
- **同一（位置, 类型）只存在一条计划刻**，重复的邻居更新不会改变触发时间。
- 计划刻执行前会校验方块类型，中途被替换则该次计划刻作废。
- 延迟：龙蛋 5 gt，其余重力方块（含铁砧）2 gt。
- 混凝土有**两条固化路径**（邻居更新时即时固化 / 实体落地固化），下落中还额外有一次液体裁剪。
- 物品掉落同时受 `dropItem` 与 `GameRules.ENTITY_DROPS` 约束。
