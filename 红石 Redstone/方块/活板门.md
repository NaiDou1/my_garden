# 活板门 Trapdoor
---
## 一、活板门的方块状态

活板门共有 5 个方块状态：

| 属性          | 类型                 | 含义                                                        | 默认值            |
| ------------- | -------------------- | ----------------------------------------------------------- | ----------------- |
| `FACING`      | `Direction`          | 活板门的水平朝向，决定打开时的旋转方向                      | `Direction.NORTH` |
| `OPEN`        | `BooleanProperty`    | 活板门是否打开                                              | `false`           |
| `HALF`        | `EnumProperty<Half>` | 活板门附着在方块的上半部分（`TOP`）还是下半部分（`BOTTOM`） | `Half.BOTTOM`     |
| `POWERED`     | `BooleanProperty`    | 是否被红石信号充能（激活）                                  | `false`           |
| `WATERLOGGED` | `BooleanProperty`    | 是否含水                                                    | `false`           |

- `FACING` 是水平方向，表示活板门关闭时贴附的墙面方向，也是打开时绕轴旋转的方向。
- `OPEN` 与 `POWERED` 通常情况下保持一致，但在玩家手动干预或爆炸触发时可能出现不同步。
- `WATERLOGGED` 表明活板门方块内部是否填充了水，属于含水方块。

## 二、放置行为

放置活板门时，会根据玩家点击的面和位置设置初始状态：

1. **决定朝向与半高**：
   - 如果玩家没有替换点击的方块，并且点击的面是**水平方向**（侧面）：
     - `FACING` = 点击的面；
     - `HALF` = 点击位置在方块竖直方向上的位置决定：若点击点 Y 坐标大于 0.5（上半部分），则为 `TOP`，否则为 `BOTTOM`。
   - 否则（点击顶面/底面，或替换点击的方块）：
     - `FACING` = 玩家水平朝向的**相反方向**；
     - `HALF` = 若点击面是 `UP`，则为 `BOTTOM`；否则为 `TOP`（点击 `DOWN` 或替换时放在上半部分）。

2. **红石信号预充能**：
   - 如果放置位置已有邻居红石信号输入（`level.hasNeighborSignal(pos)` 为 `true`），则初始状态设为 `OPEN=true`，`POWERED=true`。

3. **含水状态**：
   - 根据放置位置原有的流体设置 `WATERLOGGED`。

## 三、红石响应与邻居更新

活板门在收到 NC 更新（邻居更新）后，会立即响应红石信号变化，**没有计划刻延迟**。

处理逻辑（仅服务端执行）：

1. 获取当前位置的红石信号 `signal = level.hasNeighborSignal(pos)`。
2. 将 `signal` 与当前 `POWERED` 状态比较：
   - 如果二者**不同**，则进入更新流程。
3. 更新流程：
   - 如果 `OPEN` 与 `signal` 不同，则将 `OPEN` 设置为 `signal`，并播放对应开关声音和游戏事件。
   - 然后将 `POWERED` 设置为 `signal`。
   - 使用 `level.setBlock(pos, state, 2)` 更新方块状态。
   - 如果更新后的状态含水，则安排一次水流计划刻。

因此，红石信号变化会立即打开或关闭活板门，并且 `OPEN` 与 `POWERED` 最终会同步为当前的信号值。

## 四、玩家交互与爆炸响应

### 玩家交互

玩家右键活板门时，会调用 `useWithoutItem`：

- 如果该活板门的 `BlockSetType` 不允许手动打开（例如铁活板门），则直接返回 `PASS`，不产生任何效果。
- 否则，执行 `toggle` 操作：
  1. 切换 `OPEN` 状态（`state.cycle(OPEN)`）；
  2. 使用 `level.setBlock(pos, updated, 2)` 更新方块；
  3. 如果更新后的状态含水，安排一次水流计划刻；
  4. 播放开关声音和相应的游戏事件（`BLOCK_OPEN` 或 `BLOCK_CLOSE`）。

注意：手动操作**不会改变** `POWERED` 状态，因此可能出现 `OPEN` 与 `POWERED` 不一致的情况

### 爆炸响应（风弹）

当爆炸能触发方块（风弹）时：

- 条件：`explosion.canTriggerBlocks()` 为 `true`，且该活板门类型支持被风弹打开（除了铁活板门以外均可以），且当前 `POWERED` 为 `false`。
- 效果：调用 `toggle`，切换 `OPEN` 状态并播放声音，与玩家手动操作相同，但不会改变 `POWERED`。

---
## 五、含水与计划刻

- 活板门实现 `SimpleWaterloggedBlock`，可以含水。
- 当活板门的状态因任何原因发生改变（红石响应、手动切换、放置等）且新状态含水时，都会尝试安排一次水的计划刻（`Fluids.WATER.getTickDelay(level)`）。
- 活板门本身**没有**覆写 `tick` 方法，因此自身没有延迟计划刻逻辑；所有红石响应都是立即的。
