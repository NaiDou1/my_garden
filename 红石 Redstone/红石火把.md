# 红石火把 Redstone Torch

## 一、方块状态
红石火把分为立在地上的红石火把和挂在墙上的红石火把，他们实际上是两个不同的方块

普通红石火把 `RedstoneTorchBlock` 只有 1 个方块状态：

| 属性  | 类型              | 含义     | 默认值 |
| ----- | ----------------- | -------- | ------ |
| `LIT` | `BooleanProperty` | 是否点亮 | `true` |

墙面红石火把 `RedstoneWallTorchBlock` 有 2 个方块状态：

| 属性     | 类型                | 含义                                                | 默认值            |
| -------- | ------------------- | --------------------------------------------------- | ----------------- |
| `FACING` | `Direction`（水平） | 火把伸出的方向；红石输入侧在 `FACING.getOpposite()` | `Direction.NORTH` |
| `LIT`    | `BooleanProperty`   | 是否点亮、号                                        | `true`            |

- 普通红石火把没有 `FACING`，模型固定朝上。
- 墙面红石火把的 `FACING` ，仅包含水平四方向。
- 放置墙面红石火把时，朝向是附着方块位置的反向；默认设置为北

## 二、计划刻的添加条件
计划刻有两种添加来源：

### 1. 常规切换计划刻

当红石火把收到NC更新时，如果当前亮灭状态与输入信号状态一致，也就是“需要翻转”，则添加 2 gt 后的计划刻：优先级为默认的 `0`。

- 当前 `LIT = true`，且附着方块有红石信号；
- 或当前 `LIT = false`，且附着方块没有红石信号。

同时，如果已经存在该红石火把的计划刻，则不会重复添加。

### 2. 烧毁重启计划刻

当红石火把触发烧毁后，会添加一个延迟为 **160 gt** 的计划刻，用于之后尝试重新点亮。
详细请见下方执行计划刻的逻辑

## 三、执行计划刻时的逻辑

计划刻执行时，红石火把会先清理掉所有超过 60 gt 的熄灭记录。

然后根据当前状态执行：

### 如果当前是点亮状态

1. 若附着方块有红石信号，则将自身方块状态设置为熄灭，即 `LIT = false`，产生 状态更新（PP）和邻居更新（NC）；
2. 记录本次熄灭，用于烧毁统计；
3. 如果在 60 gt 内同一红石火把已经记录了 8 次熄灭，则触发烧毁：
   - 保持熄灭状态；
   - 产生红石火把烧毁事件，播放声音，显示粒子等。
   - 添加延迟为 160 gt 的重启计划刻。
4. 若附着方块没有红石信号，则无操作，保持点亮。

### 如果当前是熄灭状态
1. 若附着方块没有红石信号，且当前不在烧毁冷却状态，则将自身方块状态设置为点亮，即 `LIT = true`，状态更新（PP）和邻居更新（NC）；
2. 若附着方块有红石信号，或者仍处于烧毁冷却状态，则保持熄灭；
