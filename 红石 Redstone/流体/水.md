# 水（流体）

本文档基于提供的 `WaterFluid`、`FlowingFluid`、`Fluid`、`FluidState` 代码整理。  
水在代码中不是一个普通方块，而是以“流体”形式存在，分成源水和流动水两种 `Fluid` 对象。

---

## 一、水的流体状态

水相关的两个流体对象：

- `Fluids.WATER`：源水
- `Fluids.FLOWING_WATER`：流动水

`FlowingFluid` 中定义了以下两个方块状态属性：

| 属性      | 类型              | 含义          | 默认值                     |
| --------- | ----------------- | ------------- | -------------------------- |
| `FALLING` | `BooleanProperty` | 是否正在下落  | `false`                    |
| `LEVEL`   | `IntegerProperty` | 流体高度/流量 | 未在当前代码中定义具体范围 |

其中：

- `FALLING` 定义于 `FlowingFluid.createFluidStateDefinition`，所以水和流动水都有该属性。
- `LEVEL` 只在 `WaterFluid.Flowing.createFluidStateDefinition` 中额外添加，因此只有流动水有 `LEVEL` 属性。
- 源水没有 `LEVEL` 属性。

源水与流动水的状态区别：

| 类型                 | `isSource(FluidState)` | `getAmount(FluidState)`           |
| -------------------- | ---------------------- | --------------------------------- |
| `WaterFluid.Source`  | 始终返回 `true`        | 固定返回 `8`                      |
| `WaterFluid.Flowing` | 始终返回 `false`       | 返回 `fluidState.getValue(LEVEL)` |

`FlowingFluid` 中还提供了两个快速构造流体状态的方法：

- `getSource(boolean falling)`：返回源水状态，并设置 `FALLING`。
- `getFlowing(int amount, boolean falling)`：返回流动水状态，设置 `LEVEL` 和 `FALLING`。

## 二、计划刻的添加条件

在当前提供的代码中，计划刻的添加发生在 `FlowingFluid.tick` 内部。

`FlowingFluid.tick` 的流程如下：

1. 如果当前流体状态不是源，则调用 `getNewLiquid` 重新计算该位置应变成的流体状态。
2. 通过 `getSpreadDelay` 计算计划刻延迟。
3. 如果计算结果 `newFluidState` 为空：
   - 将当前流体状态置为空；
   - 将方块状态设为空气；
   - 调用 `level.setBlockAndUpdate(pos, Blocks.AIR.defaultBlockState())`。
   - 不会添加计划刻。
4. 如果计算结果 `newFluidState` 非空且与当前 `fluidState` 不同：
   - 更新当前流体状态和方块状态；
   - 调用 `level.scheduleTick(pos, fluidState.getType(), tickDelay)` 添加下一次计划刻。

其中：

- `getSpreadDelay` 默认实现直接返回 `getTickDelay(level)`。
- 水的 `getTickDelay` 返回 `5`，因此计划刻延迟为 `5 gt`。
- 源流体在当前 `FlowingFluid.tick` 中没有调度自身的代码。

需要注意：

> 流动水方块最初的计划刻添加条件，例如放置水、方块更新后首次调度，不在当前给出的代码中。  
> 这些逻辑通常与 `LiquidBlock` 相关，需要额外提供 `LiquidBlock` 代码才能确定。

## 三、执行计划刻时的逻辑

计划刻执行入口是 `FlowingFluid.tick`。

具体逻辑如下：

### 3.1 非源流体

如果当前 `fluidState.isSource()` 为 `false`：

1. 计算：
   ```java
   FluidState newFluidState = this.getNewLiquid(level, pos, level.getBlockState(pos));
   int tickDelay = this.getSpreadDelay(level, pos, fluidState, newFluidState);
   ```

2. 若 `newFluidState.isEmpty()`：
   - 将该位置恢复为空气。
   - 不添加新的计划刻。

3. 若 `newFluidState != fluidState`：
   - 更新流体状态；
   - 将流体状态转换为对应的方块状态并更新；
   - 添加下一次计划刻。

4. 最后无论是否变化，都会调用：
   ```java
   this.spread(level, pos, blockState, fluidState);
   ```

### 3.2 源流体

如果当前 `fluidState.isSource()` 为 `true`：

- 不会执行上面非源的状态重算和计划刻调度；
- 直接执行 `spread`。

因此源水的计划刻执行主要目的是尝试向周围扩散，而不是改变自身状态。

## 四、水的扩散与流动

水的扩散核心在 `FlowingFluid.spread`、`spreadToSides`、`getSpread`、`getNewLiquid` 和 `getSlopeDistance` 中。

### 4.1 向下传播

`spread` 首先检查下方方块：

1. 调用 `canMaybePassThrough` 判断能否从当前位置向下穿过。
2. 如果可以穿过：
   - 调用 `getNewLiquid(level, belowPos, belowState)` 计算下方应变成的流体状态。
   - 检查下方当前流体 `belowFluid.canBeReplacedWith(...)`。
   - 检查下方方块是否能容纳对应流体 `canHoldSpecificFluid(...)`。
3. 如果条件满足：
   - 调用 `spreadTo` 将新流体写入下方位置。
   - 如果当前流体的水平源邻居数量 `sourceNeighborCount >= 3`，则额外调用 `spreadToSides` 向水平方向扩散。
   - 然后返回，不再继续水平扩散。

如果向下传播失败：

- 如果当前流体是源，或者当前位置不是“水洞”，则调用 `spreadToSides` 水平扩散。

### 4.2 水平扩散

`spreadToSides` 的逻辑如下：

1. 计算水平可传播的流体量：
   ```java
   int neighbor = fluidState.getAmount() - this.getDropOff(level);
   if (fluidState.getValue(FALLING)) {
       neighbor = 7;
   }
   ```
2. 如果 `neighbor > 0`，调用 `getSpread` 得到可以传播的方向和对应流体状态。
3. 对每个可传播方向，调用 `spreadTo` 写入相邻位置。

水的 `getDropOff` 返回 `1`，因此水平每传播一格，流体高度量通常减少 `1`。

### 4.3 路径选择

`getSpread` 中会使用 `getSlopeDistance` 计算到“可下落位置”的距离，优先选择距离更短的路径。

- 水的 `getSlopeFindDistance` 返回 `4`。
- 这意味着水在水平扩散时，最多会递归搜索约 4 格内的下落路径。

### 4.4 新流体状态计算：`getNewLiquid`

`getNewLiquid` 是水流动的关键方法，逻辑如下：

1. 检查水平四个方向的同类流体：
   - 统计最高 `fluidState.getAmount()`；
   - 统计源流体数量。
   - 只有能通过 `canPassThroughWall` 的方向才计入。

2. 如果水平源邻居数量 `>= 2`，且 `canConvertToSource(level)` 返回 `true`：
   - 检查下方方块是否为实心，或者下方流体是同类源；
   - 如果满足，则返回源水状态：
     ```java
     return this.getSource(false);
     ```

3. 检查上方：
   - 如果上方有同类流体，且能从上方通过：
     - 返回下落流：
       ```java
       return this.getFlowing(8, true);
       ```

4. 否则：
   - 计算：
     ```java
     int amount = highestNeighbor - this.getDropOff(level);
     ```
   - 如果 `amount <= 0`，返回空流体状态。
   - 否则返回：
     ```java
     return this.getFlowing(amount, false);
     ```

对水来说：

- `canConvertToSource` 返回：
  ```java
  level.getGameRules().get(GameRules.WATER_SOURCE_CONVERSION)
  ```
- 即水的无限水源转换由游戏规则 `WATER_SOURCE_CONVERSION` 控制。

## 五、水的可替换性

`WaterFluid.canBeReplacedWith` 的实现为：

```java
return direction == Direction.DOWN && !other.is(FluidTags.WATER);
```

含义是：

- 当前已有水时，只有在方向为 `DOWN` 且新流体不是水时，水才会被替换。
- 这会影响水在向下传播时与其他流体的替换关系。

此外，`WaterFluid.isSame` 将源水和流动水都视为同一种流体：

```java
return other == Fluids.WATER || other == Fluids.FLOWING_WATER;
```

## 六、实体交互

`WaterFluid.entityInside` 中只做了一件事：

```java
effectApplier.apply(InsideBlockEffectType.EXTINGUISH);
```

即向实体应用“熄灭”效果。

但具体实体的灭火逻辑，例如清除实体的火焰状态、处理实体身上的火焰时间等，不在当前代码中。需要查看 `InsideBlockEffectApplier` 以及实体类对 `InsideBlockEffectType.EXTINGUISH` 的处理。

水的推动实体速度计算在 `FlowingFluid.getFlow` 中：

- 遍历水平四个方向，比较相邻流体的 `getOwnHeight()`；
- 若存在高度差，则累加水平方向向量；
- 如果当前流体处于 `FALLING` 状态，且某个水平方向或上方存在实体面，则额外施加向下速度 `-6.0`；
- 最后返回归一化后的流向。

## 七、渲染与形状

### 7.1 高度

- `WaterFluid` 继承 `FlowingFluid.getOwnHeight`：
  ```java
  return fluidState.getAmount() / 9.0F;
  ```
- `FlowingFluid.getHeight`：
  - 如果上方是同类流体，返回 `1.0F`；
  - 否则返回 `fluidState.getOwnHeight()`。

### 7.2 形状

`FlowingFluid.getShape`：

- 如果 `getAmount() == 9` 且上方是同类流体，返回完整方块形状 `Shapes.block()`；
- 否则返回一个从底面到 `fluidState.getHeight(level, pos)` 高度的长方体。

### 7.3 动画

`WaterFluid.animateTick`：

- 如果流体不是源且没有 `FALLING`：
  - 有 `1/64` 概率播放 `WATER_AMBIENT` 环境音。
- 否则（源水或下落流）：
  - 有 `1/10` 概率生成 `UNDERWATER` 粒子。

### 7.4 滴落粒子

`WaterFluid.getDripParticle` 返回 `ParticleTypes.DRIPPING_WATER`。

## 八、破坏方块与掉落

`WaterFluid.beforeDestroyingBlock`：

- 如果方块有方块实体，则获取方块实体；
- 调用 `Block.dropResources(state, level, pos, blockEntity)` 掉落方块资源。

这意味着水在冲走某些方块时，会以破坏方块的掉落物形式掉落资源。
