# 水 Water（流体）
---

> 水由「流体（`Fluid` / `FluidState`）+ 承载方块（`LiquidBlock`，即 `minecraft:water`）」两部分组成：
> 流体负责状态与扩散规则，方块负责持有状态、响应更新、申请计划刻。二者通过 `FluidState.createLegacyBlock()`
> 与 `LiquidBlock.getFluidState()` 互相换算。**水不参与随机刻**，全部流动都由计划刻（流体刻）驱动。

## 一、水的状态

水有两个流体：`Fluids.WATER`（水源）与 `Fluids.FLOWING_WATER`（流动水）。

| 流体            | 实现类               | 属性      | 类型                    | 含义             | 默认值  |
| --------------- | -------------------- | --------- | ----------------------- | ---------------- | ------- |
| `WATER`（源）   | `WaterFluid.Source`  | `FALLING` | `BooleanProperty`       | 是否处于下落状态 | `false` |
| `FLOWING_WATER` | `WaterFluid.Flowing` | `LEVEL`   | `IntegerProperty(1..8)` | 水量             | `8`     |
|                 |                      | `FALLING` | `BooleanProperty`       | 是否处于下落状态 | `false` |

- 源的 `getAmount()` 恒为 8、`isSource() = true`；流动水的 `getAmount() = LEVEL`、`isSource() = false`。
- 流体高度 `getOwnHeight = amount / 9`；若上方有同种流体，高度按 1.0 计算（视觉上连成整格）。
- 换算到方块状态（`LiquidBlock` 的 `level`，0..15）：
  - `level = 0` → 水源；
  - `level = 1..7` → 流动水，水量 `8 - level`（level 1 水量 7 …… level 7 水量 1）；
  - `level = 8` → 下落状态（水量按 8 计）。
- 水的方块属性：`replaceable`、`noCollision`、`strength 100`、`PushReaction.POPPED`、`noLootTable`、`liquid()`、渲染不可见、不掉落物品。
- 只有水源能用水桶取回；流动水取桶返回空。

## 二、计划刻的添加条件

水的计划刻分**方块层**与**流体层**两个来源，延迟都是流体的 `getTickDelay()` = **5 gt**，优先级默认 0。

**方块层（`LiquidBlock`）——3 个入口：**

| 入口                            | 条件                                                                                         |
| ------------------------------- | -------------------------------------------------------------------------------------------- |
| 被放置时（`onPlace`）           | 若 `shouldSpreadLiquid` 为真 → 排 5 gt。对水而言该判断恒为真（该判断只对熔岩遇水时才返回假） |
| 邻居变化时（`neighborChanged`） | 同上，恒排 5 gt                                                                              |
| 形状更新时（`updateShape`）     | **仅在**「自身是水源」**或**「触发更新的邻居是水源」时排 5 gt（比方块类的形状更新更严格）    |

**含水方块（`SimpleWaterloggedBlock.placeLiquid`）**：放置水时把 `WATERLOGGED` 置 `true`，并排 5 gt 流体刻。

**气泡柱（`LiquidBlock`）**：水下有灵魂沙/岩浆块的满格水源，会额外排 20 gt 的**方块刻**（不是流体刻）。

**流体层（`FlowingFluid.tick` 内部重排）**：仅当**自己不是源**、且重算出的新流体状态与当前不同时，
更新自身方块后**再排一次 5 gt**；若重算结果是「空」则直接变空气、不再重排。
→ 因此**水源不会给自己重排**，它只会被方块层的更新唤醒。

补充规则：

- 流体刻与方块刻是**两套独立队列**，同一游戏刻内**先跑方块刻（`blockTicks`）、再跑流体刻（`fluidTicks`）**，单刻各上限 65536。
- 去重键是（位置, **流体类型**）：`WATER`（源）与 `FLOWING_WATER`（流动）是不同的类型，互不覆盖，各自可存在一条计划刻。
- 目标区块未加载时该次调度被丢弃。

## 三、执行计划刻时的逻辑

计划刻执行时：

1. 先校验该位置的流体**仍是同一种流体类型**；否则本次计划刻作废。
2. `FlowingFluid.tick` 的顺序：
   - **若是水源** → 不重算水量，直接跳到第 3 步「扩散」；
   - **若不是源**：
     1. 用 `getNewLiquid` 重算该位置应有的流体（见第 3 步）；取扩散延迟 `getSpreadDelay`（水 = 5 gt）；
     2. 重算结果为空 → 该位置变空气，且**不再重排**；
     3. 重算结果与当前不同 → 更新方块状态 + 按延迟**重排一次**流体刻；
   - 最后**无条件**执行「扩散」。
3. `getNewLiquid` 的判定顺序（水平邻居 → 变源 → 上方 → 衰减）：
   1. 遍历**四个水平方向**：对方是同种流体、且两侧碰撞形状不互相遮挡（能穿墙）时，取其中**最高的水量**；若对方是源则「源邻居计数」+1。
   2. 源邻居计数 **≥ 2** 且游戏规则 `WATER_SOURCE_CONVERSION` 开启 且 下方是实心方块或同种水源 → **本格变成水源**。
   3. 否则若**上方**是同种流体且能穿墙 → 变成 `falling = true` 的下落水（水量按 8）。
   4. 否则水量 = 最高邻居水量 **− 1**（`getDropOff = 1`）；≤ 0 → 变成空（`Fluids.EMPTY`）。
4. 「扩散」`spread` 的顺序：
   1. **优先向下**：下方能穿过 且 下方能容纳水 → 用 `getNewLiquid` 算出下方应有的水；若下方当前流体允许被替换且能容纳 → 向下放置水；
      此时若**水平方向的水源邻居数 ≥ 3**，**同时**再向侧面扩散一次；然后 return。
   2. 否则（自身是源，**或**下方不是「水洞」）→ 只向侧面扩散。
   - 「水洞」= 下方能穿过，且下方已是同种流体或能容纳水（即“水能往下走”）。
5. 向侧面扩散（`spreadToSides`）：以「自身水量 − 1」为传播水量（处于下落状态时固定按 7 计）；只有传播水量 > 0 才扩散。
6. 侧向方向的选择（`getSpread` / `getSlopeDistance`）：
   - 对四个水平方向，能穿过的方向才参与；
   - 若该方向的下一格紧邻一个「水洞」，距离记为 0（**直接优先**）；
   - 否则以该方向为起点**向外递归搜索**，最多 4 格（水的 `getSlopeFindDistance = 4`），取能到达水洞的最短路径长度；
   - 只保留**距离最小**的那些方向（并列则全部保留），且还要满足「新水能替换该处旧流体」和「该处能容纳水」。
7. 落子（`spreadTo`）：目标是含水方块/炼药锅一类的 `LiquidBlockContainer` → 调用 `placeLiquid`（只置 `WATERLOGGED`，不改方块）；
   否则若目标不是空气，先按方块掉落规则破坏它（`beforeDestroyingBlock`），再 `setBlockAndUpdate(流体对应的 water 方块状态)`。

> 水的流动方向向量（`getFlow`）另有一套计算，只影响实体被推动的方向与贴图流动方向，不影响扩散判定。

## 四、水的响应流程

- **放置水（水桶 / 流体生成）**
  - 目标是可替换的方块或空气 → `setBlock(水的 legacy 方块, flags=11)`；目标是 `LiquidBlockContainer`（含水方块、炼药锅等）→ `placeLiquid`。
  - 之后由 `onPlace` 排 5 gt 流体刻 → 5 gt 后按第三节流程扩散。

- **相邻方块变化**
  - `neighborChanged`：恒排 5 gt。
  - `updateShape`：仅当自身是源或邻居是源时排 5 gt。
  - 于是「挖掉水源下方的方块」会唤醒水源，5 gt 后开始向下/向侧流动。

- **源 → 流动**
  - 源被唤醒后：下方有水洞 → 向下扩散并变成下落水；下方没有水洞 → 向侧面扩散。
  - 侧向每经过一格水量 −1，最多流 7 格（水量 8 → 1）；下落状态不衰减。

- **流动 → 源**
  - 重算时水平源邻居 ≥ 2、下方是实心或水源、且 `WATER_SOURCE_CONVERSION` 开启 → 变成水源（无限水）。
  - 若该规则关闭，则永远不会自发变源。

- **流动 → 空气（回流）**
  - 重算水量 ≤ 0（周围没有更高的同种水）→ 该格变空气，不再重排；其邻居会在各自的刻里继续回退。

- **下落水（`falling = true`）**
  - 上方有同种流体时本格为下落水，水量按 8 处理，可直接补满；落到实心方块上方后转为普通流动水并向侧面铺开。

- **与熔岩相遇（判定发生在熔岩一侧与下落交汇处）**
  - 水从上方流到熔岩上 → 该处变石头；
  - 水出现在熔岩方块旁边 → 熔岩源变黑曜石、流动熔岩变圆石（由熔岩方块的 `shouldSpreadLiquid` 处理）；
  - 水比熔岩高 ≥ 0.444 时允许水替换熔岩。

- **含水方块（`WATERLOGGED`）**
  - 放水 → 方块不变、属性置真；取水 → 属性置假，若此时方块无法存活则连带破坏（掉落）。
  - 含水方块的流体刻与普通水共用同一套扩散逻辑，但 `spreadTo` 走 `placeLiquid` 分支，不会把方块冲掉。

- **结冰 / 积雪**
  - 与流体刻无关：由区块随机刻里的降水处理（每刻 1/48 概率）按生物群系 `shouldFreeze` 把水面变为冰。

## 五、判定顺序要点

- **两类流体分工**：`WATER`（源）在刻内**不重算、只扩散**；`FLOWING_WATER`（流动）刻内**先重算、可能重排、再扩散**。
- **衰减规则**：水平每格 −1，最多 7 格；下落状态不衰减，落地后向侧铺开。
- **优先级**：先向下（水洞），没有向下出路才向侧面；向侧面时只走“能最快到达水洞”的方向（搜索深度 4）。
- **变源条件**：水平源邻居 ≥ 2 + 下方实心或水源 + `WATER_SOURCE_CONVERSION` 规则。
- **排刻入口不同**：放置与邻居变化恒排 5 gt；形状更新只在「自身或邻居是源」时排；流动水靠自身状态变化重排。
- **去重键 =（位置, 流体类型）**，源与流动水互不覆盖；同一刻内方块刻先于流体刻执行。
- **水不随机刻**；随机刻只用于降水相关的结冰/积雪。
- 与熔岩的反应分别写在两处：熔岩方块侧的水邻居判定（黑曜石/圆石）与熔岩向下流入水（石头）。
