# 水（流体）

本文档基于提供的 `WaterFluid`、`FlowingFluid`、`Fluid`、`FluidState`、`LiquidBlock`、`LiquidBlockContainer` 以及 `CauldronInteractions` 代码整理。  
水在 Minecraft 中既表现为流体（`Fluid`），也通过 `LiquidBlock` 以方块形式存在。以下分别从方块状态、计划刻调度、流动逻辑等方面描述。

---

## 一、水的方块状态

水对应的方块为 `LiquidBlock`，具体实例是 `Blocks.WATER`。

### 1.1 方块状态属性

`LiquidBlock` 定义了如下方块状态：

| 属性    | 类型              | 含义         | 默认值 |
| ------- | ----------------- | ------------ | ------ |
| `LEVEL` | `IntegerProperty` | 流体高度等级 | `0`    |

`LEVEL` 的实际取值范围是 `0` 到 `15`（继承自 `BlockStateProperties.LEVEL`），但 `LiquidBlock` 内部只使用了 `0` 到 `8`，大于 `8` 的值会被映射为 `8` 处理。

### 1.2 方块状态与流体状态的映射

`LiquidBlock` 内部维护了一个 `stateCache` 列表，缓存了所有可能出现的 `FluidState`：

| 方块 `LEVEL` | 缓存的 `FluidState`          | 流体类型 | `getAmount()` | `FALLING` | 说明                         |
| ------------ | ---------------------------- | -------- | ------------- | --------- | ---------------------------- |
| `0`          | `fluid.getSource(false)`     | 源水     | 8             | false     | 源水                         |
| `1`          | `fluid.getFlowing(7, false)` | 流动水   | 7             | false     | 7/8 高度                     |
| `2`          | `fluid.getFlowing(6, false)` | 流动水   | 6             | false     | 6/8 高度                     |
| `3`          | `fluid.getFlowing(5, false)` | 流动水   | 5             | false     | 5/8 高度                     |
| `4`          | `fluid.getFlowing(4, false)` | 流动水   | 4             | false     | 4/8 高度                     |
| `5`          | `fluid.getFlowing(3, false)` | 流动水   | 3             | false     | 3/8 高度                     |
| `6`          | `fluid.getFlowing(2, false)` | 流动水   | 2             | false     | 2/8 高度                     |
| `7`          | `fluid.getFlowing(1, false)` | 流动水   | 1             | false     | 1/8 高度                     |
| `8`          | `fluid.getFlowing(8, true)`  | 流动水   | 8             | true      | 满且下落                     |
| `9`-`15`     | 同 `LEVEL=8`                 | 流动水   | 8             | true      | 被 `Math.min(level, 8)` 截断 |

`getFluidState(BlockState state)` 方法通过 `state.getValue(LEVEL)` 取索引，并使用 `Math.min(level, 8)` 保证不越界。

因此，玩家可以看到的方块状态 `LEVEL` 直接决定了该位置实际的水流高度和是否下落。

## 二、计划刻的添加条件

水的计划刻添加分为两个层面：

1. **方块层面**：`LiquidBlock` 在方块状态变化或邻居变化时调度**流体类型的计划刻**。
2. **流体层面**：`FlowingFluid.tick` 内部会根据计算出的新流体状态调度下一次计划刻。

### 2.1 方块层面的调度

`LiquidBlock` 在以下方法中会调度流体计划刻：

#### 2.1.1 `onPlace`

当水方块被放置时：

```java
if (this.shouldSpreadLiquid(level, pos, state)) {
    level.scheduleTick(pos, state.getFluidState().getType(), this.fluid.getTickDelay(level));
}
```

- `shouldSpreadLiquid` 对于水（`this.fluid.is(FluidTags.LAVA)` 为 `false`）**始终返回 `true`**。
- 因此，**任何水方块被放置后，都会立即调度一个流体计划刻**。
- 调度的是当前方块位置对应的 `Fluid` 类型（源水或流动水）的计划刻，延迟为 `this.fluid.getTickDelay(level)`，对水来说是 `5`。

#### 2.1.2 `neighborChanged`

当水方块收到邻居方块变化通知时：

```java
if (this.shouldSpreadLiquid(level, pos, state)) {
    level.scheduleTick(pos, state.getFluidState().getType(), this.fluid.getTickDelay(level));
}
```

- 对水而言，`shouldSpreadLiquid` 仍然返回 `true`。
- 因此，**水方块在邻居变化时也会调度一次流体计划刻**。

#### 2.1.3 `updateShape`

当水方块自身或因邻居变化触发形状更新时：

```java
if (state.getFluidState().isSource() || neighbourState.getFluidState().isSource()) {
    ticks.scheduleTick(pos, state.getFluidState().getType(), this.fluid.getTickDelay(level));
}
```

- 仅当**当前流体为源水**，或者**触发更新的邻居方块的流体为源水**时，才会调度流体计划刻。
- 这个条件不会对普通流动水因邻居变化而触发，主要用于源水在邻近方块改变时重新检查自身的扩散（例如无限水源的形成）。

### 2.2 流体层面的调度

`FlowingFluid.tick` 在执行计划刻时，若当前流体状态发生变化，会为自己调度下一次计划刻：

```java
if (newFluidState != fluidState) {
    fluidState = newFluidState;
    blockState = fluidState.createLegacyBlock();
    level.setBlockAndUpdate(pos, blockState);
    level.scheduleTick(pos, fluidState.getType(), tickDelay);
}
```

- 这只发生在非源流体中。
- `tickDelay` 来自 `getSpreadDelay`，水的实现直接返回 `getTickDelay(level)`，即 `5`。
- 因此流动水在每次执行计划刻后，如果状态有变，会继续以 `5 gt` 的间隔调度下一次计划刻，直到状态稳定（例如水消失或达到稳定高度）。

**总结**：水初始的计划刻由 `LiquidBlock` 的放置和邻居更新触发；后续持续的计划刻由 `FlowingFluid.tick` 自行调度。

## 三、执行计划刻时的逻辑

水的计划刻执行实际上调用的是**流体类型的 `tick` 方法**，即 `FlowingFluid.tick`（定义在 `FlowingFluid` 中）。此外，`LiquidBlock` 自身也有一个方块计划刻 `LiquidBlock.tick`，但主要用于气泡柱更新，不影响水流核心逻辑。

### 3.1 流体计划刻：`FlowingFluid.tick`

入口：

```java
public void tick(final ServerLevel level, final BlockPos pos, BlockState blockState, FluidState fluidState) {
    if (!fluidState.isSource()) {
        FluidState newFluidState = this.getNewLiquid(level, pos, level.getBlockState(pos));
        int tickDelay = this.getSpreadDelay(level, pos, fluidState, newFluidState);
        if (newFluidState.isEmpty()) {
            fluidState = newFluidState;
            blockState = Blocks.AIR.defaultBlockState();
            level.setBlockAndUpdate(pos, blockState);
        } else if (newFluidState != fluidState) {
            fluidState = newFluidState;
            blockState = fluidState.createLegacyBlock();
            level.setBlockAndUpdate(pos, blockState);
            level.scheduleTick(pos, fluidState.getType(), tickDelay);
        }
    }
    this.spread(level, pos, blockState, fluidState);
}
```

#### 3.1.1 非源流体

1. 调用 `getNewLiquid(level, pos, level.getBlockState(pos))` 重新计算该位置应有的流体状态。
2. 若计算结果为空（`Fluids.EMPTY.defaultFluidState()`）：
   - 将当前流体状态设为空；
   - 将方块状态替换为空气；
   - 使用 `setBlockAndUpdate` 更新世界；
   - **不**添加新的计划刻。
3. 若计算结果非空且与当前流体状态不同：
   - 更新 `fluidState` 和 `blockState`；
   - 将新方块状态写入世界；
   - 调用 `level.scheduleTick(pos, fluidState.getType(), tickDelay)` 调度下一次计划刻。
4. 无论是否发生状态变化，最后都调用 `this.spread(level, pos, blockState, fluidState)` 尝试向周围扩散。

#### 3.1.2 源流体

- 跳过状态重算和计划刻调度，直接执行 `spread`。
- 源水不会因 tick 自身消失或改变高度，它的作用是通过 `spread` 向周围产生流动水。

### 3.2 方块计划刻：`LiquidBlock.tick`

```java
@Override
protected void tick(final BlockState state, final ServerLevel level, final BlockPos pos, final RandomSource random) {
    if (shouldBubbleColumnOccupy(state)) {
        BlockState stateBelow = level.getBlockState(pos.below());
        BubbleColumnBlock.updateColumn(Blocks.BUBBLE_COLUMN, level, pos, stateBelow);
    }
}
```

- 这个方块 tick 仅在满足气泡柱条件时执行（`shouldBubbleColumnOccupy` 为 `true`）。
- 与水的流动、扩散无关。
- 水的方块 tick 调度的条件由 `tryScheduleBubbleBlockColumn` 负责，并且延迟为 `20`。

## 四、水的扩散与流动

水的扩散核心逻辑在 `FlowingFluid` 中。

### 4.1 向下传播

`spread` 首先尝试向下传播：

1. 检查当前方块下方能否通过：`canMaybePassThrough(level, pos, state, Direction.DOWN, belowPos, belowState, belowFluid)`。
2. 若可以通过：
   - 计算下方应变成的流体状态：`getNewLiquid(level, belowPos, belowState)`。
   - 检查下方当前流体能否被替换：`belowFluid.canBeReplacedWith(level, belowPos, newBelowFluidType, Direction.DOWN)`。
   - 检查下方方块是否能容纳该流体：`canHoldSpecificFluid(level, belowPos, belowState, newBelowFluidType)`。
3. 若条件满足：
   - 调用 `spreadTo(level, belowPos, belowState, Direction.DOWN, newBelowFluid)` 将流体写入下方。
   - 若当前流体的水平源邻居数量 `sourceNeighborCount(level, pos) >= 3`，则再调用 `spreadToSides` 水平扩散。
   - 方法返回，不再进行水平扩散。
4. 若向下传播失败：
   - 如果当前流体是源，或者当前不是“水洞”，则调用 `spreadToSides` 水平扩散。

### 4.2 水平扩散

`spreadToSides` 逻辑：

1. 计算可传播的流体量：
   ```java
   int neighbor = fluidState.getAmount() - this.getDropOff(level);
   if (fluidState.getValue(FALLING)) {
       neighbor = 7;
   }
   ```
2. 若 `neighbor > 0`，调用 `getSpread(level, pos, state)` 获取可传播方向和对应新流体状态。
3. 对每个可传播方向，调用 `spreadTo` 写入相邻方块。

对于水：
- `getDropOff` 返回 `1`，所以水平每传播一格，流体高度 `amount` 降低 `1`。
- 若当前是下落的流体，则水平传播时按 `7` 计算，使下落水流在水平方向也能扩散较多。

### 4.3 路径选择：`getSpread` 和 `getSlopeDistance`

- `getSpread` 会通过 `getSlopeDistance` 计算从候选位置到达“可下落位置”的距离，选择距离最短的方向。
- 水的 `getSlopeFindDistance` 返回 `4`，即最多递归搜索 4 格远的可下落路径。
- 如果候选位置本身是“水洞”（下方可下落），则距离为 `0`，优先选择。

### 4.4 新流体状态计算：`getNewLiquid`

`getNewLiquid` 是水状态变化的核心：

1. 统计水平四个方向的同类流体：
   - 只考虑可以通过 `canPassThroughWall` 的方向。
   - 记录最大 `amount` 和源流体数量。
2. 若水平源邻居数量 `>= 2` 且 `canConvertToSource(level)` 为 `true`：
   - 检查下方方块是否为实心，或下方流体是同类源；
   - 若满足，则返回源水 `getSource(false)`。
3. 检查上方：
   - 如果上方有同类流体且可以穿过，则返回下落流 `getFlowing(8, true)`。
4. 否则：
   - 计算 `amount = highestNeighbor - getDropOff(level)`。
   - 若 `amount <= 0`，返回空流体状态。
   - 否则返回 `getFlowing(amount, false)`。

水的 `canConvertToSource` 取决于游戏规则 `WATER_SOURCE_CONVERSION`，控制无限水源是否生效。

## 五、水的可替换性

`WaterFluid.canBeReplacedWith`：

```java
return direction == Direction.DOWN && !other.is(FluidTags.WATER);
```

- 当方向为 `DOWN` 且新流体不是水时，水可以被替换。
- 这常用于水向下流入岩浆等场景（生成石头等），具体混合逻辑不在当前代码中。

此外，`WaterFluid.isSame` 认为源水和流动水是同一种流体：

```java
return other == Fluids.WATER || other == Fluids.FLOWING_WATER;
```

## 六、实体交互

### 6.1 灭火

`WaterFluid.entityInside`：

```java
effectApplier.apply(InsideBlockEffectType.EXTINGUISH);
```

- 向实体应用“熄灭”效果。
- 具体灭火逻辑由 `InsideBlockEffectApplier` 和实体类处理，不在当前代码中。

### 6.2 推动实体

`FlowingFluid.getFlow`：

- 比较水平四个方向相邻流体的 `getOwnHeight()`；
- 存在高度差时累加水平方向向量；
- 若当前流体 `FALLING` 且某方向存在可站立面，则额外施加向下速度 `-6.0`；
- 返回归一化的流动向量。

## 七、渲染与形状

### 7.1 高度与形状

- `FlowingFluid.getOwnHeight`：`fluidState.getAmount() / 9.0F`
- `FlowingFluid.getHeight`：若上方为同类流体，返回 `1.0F`，否则返回 `getOwnHeight()`
- `FlowingFluid.getShape`：若 `amount == 9` 且上方同类流体，返回完整方块形状；否则返回高度为 `getHeight` 的长方体。

### 7.2 动画

`WaterFluid.animateTick`：

- 非源且非下落流：`1/64` 概率播放 `WATER_AMBIENT` 环境音。
- 源或下落流：`1/10` 概率生成 `UNDERWATER` 粒子。

### 7.3 滴落粒子

`WaterFluid.getDripParticle` 返回 `ParticleTypes.DRIPPING_WATER`。

## 八、破坏方块与掉落

`WaterFluid.beforeDestroyingBlock`：

```java
BlockEntity blockEntity = state.hasBlockEntity() ? level.getBlockEntity(pos) : null;
Block.dropResources(state, level, pos, blockEntity);
```

- 水在冲走方块时，会调用 `Block.dropResources` 生成掉落物。
- 具体哪些方块会被水冲走，由 `BlockTags.WASHED_AWAY_BY_FLUIDS` 标签决定（在 `FlowingFluid.canHoldAnyFluid` 中使用）。

## 九、水方块与桶交互

`LiquidBlock` 实现了 `BucketPickup` 接口：

```java
@Override
public ItemStack pickupBlock(final @Nullable LivingEntity user, final LevelAccessor level, final BlockPos pos, final BlockState state) {
    if (state.getValue(LEVEL) == 0) {
        level.setBlock(pos, Blocks.AIR.defaultBlockState(), 11);
        return new ItemStack(this.fluid.getBucket());
    } else {
        return ItemStack.EMPTY;
    }
}
```

- 仅当方块 `LEVEL == 0`（源水）时，使用空桶可以取水。
- 取水后该位置变成空气。
- 返回对应的水桶物品（`Items.WATER_BUCKET`）。
