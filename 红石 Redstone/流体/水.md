# 水 Water（流体）
---

> 水由「流体（`Fluid` / `FluidState`）+ 承载方块（`LiquidBlock`，即 `minecraft:water`）」两部分组成：
> 流体负责状态与扩散规则，方块负责持有状态、响应更新、申请计划刻。二者通过 `FluidState.createLegacyBlock()`
> 与 `LiquidBlock.getFluidState()` 互相换算。 
> 
> **水不参与随机刻**，全部流动都由计划刻（流体刻）驱动。

## 一、水的状态

水有两个流体：`Fluids.WATER`（水源）与 `Fluids.FLOWING_WATER`（流动水）。

| 流体            | 属性      | 类型                    | 含义             | 默认值  |
| --------------- | --------- | ----------------------- | ---------------- | ------- |
| `WATER`（水源） | `FALLING` | `BooleanProperty`       | 是否处于下落状态 | `false` |
| `FLOWING_WATER` | `LEVEL`   | `IntegerProperty(1..8)` | 水量             | `8`     |
|                 | `FALLING` | `BooleanProperty`       | 是否处于下落状态 | `false` |

- 源的`水量`恒为 8、`isSource() = true`；流动水的`水量` = LEVEL
- 流体高度 `= 水量 / 9`；若上方有同种流体，高度按 1.0 计算（视觉上连成整格）。
- 换算到方块状态（`LiquidBlock` 的 `level`，0..15）：
  - `level = 0` → 水源；
  - `level = 1..7` → 流动水，水量 `8 - level`（level 1 水量 7 …… level 7 水量 1）；
  - `level = 8` → 下落状态（水量按 8 计）
- 只有水源能用水桶取回；流动水取桶返回空。

## 二、计划刻的添加条件

水的计划刻分**方块**与**流体**两个来源，延迟都是流体的 `getTickDelay()` = **5 gt**，优先级默认 0。

**方块层（`LiquidBlock`）**

| 入口                            | 条件                                                                                                             |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 被放置时（`onPlace`）           | 若 `shouldSpreadLiquid` 为真 → 添加一个延迟为 5 gt的计划刻。对水而言该判断恒为真（该判断只对熔岩遇水时才返回假） |
| 邻居变化时（`neighborChanged`） | 同上，恒添加 5 gt的计划刻                                                                                        |
| 形状更新PP时（`updateShape`）   | **仅在**「自身是水源」**或**「触发更新的邻居是水源」时添加计划 5 gt计划刻                                        |

**含水方块（`SimpleWaterloggedBlock.placeLiquid`）**：放置水时把 `WATERLOGGED` 置 `true`，并添加 5 gt 流体计划刻。

**气泡柱（`LiquidBlock`）**：水下有灵魂沙/岩浆块的满格水源，会额外添加计划 20 gt 的**方块计划刻**（不是流体）。

**流体层（`FlowingFluid.tick` 内部重添加计划刻）**：仅当**自己不是源**、且重算出的新流体状态与当前不同时，
更新自身方块后**再添加计划一次 5 gt**；若重算结果是「空」则直接变空气、不再重添加计划。
→ 因此**水源不会给自己重添加计划**，它只会被方块层的更新唤醒。

补充规则：

- 流体计划刻刻与方块计划刻刻是**两套独立队列**，同一游戏刻内**先进行方块计划刻（`blockTicks`）、再执行流体计划刻事件（`fluidTicks`）**，单刻各上限 65536。
- 去重键是（位置, **流体类型**）：`WATER`（源）与 `FLOWING_WATER`（流动）是不同的类型，互不覆盖，各自可存在一条计划刻。

## 水的理论水量计算方法

`getNewLiquid`：这一格现在应该是什么


 **先扫四个水平邻居**。只有「同种流体」且「能chuangu」的邻居才计入。
>「能穿过」指两侧方块的碰撞形状没有互相遮挡对方那一面

   统计出这些邻居里**最高的水量**，同时数一下其中有几个是**水源**。


  以下按优先级从高到低判断，命中一条就返回：
1. **变源判定**（优先级最高）：水平水源邻居数 ≥ 2，且游戏规则 `WATER_SOURCE_CONVERSION` 为真，且下方是实心方块或同种水源 → 这一格变成**水源**
2. **上方判定**：上方是同种流体且能穿过 → 这一格变成 `falling = true` 的**下落水**，水量按 8 处理（所以水柱内部始终是满的，不衰减）。
3. **衰减**：以上都不满足时，水量 = 最高的邻居水量 − 1。若结果 ≤ 0，说明周围没有比这里更高的水，返回**空**，这一格会变成空气（水流回退）。


## 三、执行计划刻时的逻辑

计划刻执行时：


先校验该位置的流体**仍是同一种流体类型**；否则本次计划刻作废。


2. 执行计划刻时的逻辑：
   - **若是水源** →直接「扩散」；
   - **若不是源**：
     1. 用 `getNewLiquid` 重算该位置应有的流体；获取扩散延迟 `getSpreadDelay`（水 = 5 gt）；
     2. 重算结果为空 → 该位置变空气，且**不再重添加计划**；
     3. 重算结果与当前不同 → 更新方块状态 + 按延迟**重添加计划一次**流体刻；
   - 最后**无条件**执行「扩散」。

3. 「扩散」`spread` 的顺序：
   1. **优先向下**：下方能穿过 且 下方能容纳水 → 用 `getNewLiquid` 算出下方应有的水；若下方当前流体允许被替换且能容纳 → 向下放置水；
      此时若**水平方向的水源邻居数 ≥ 3**，**同时**再向侧面扩散一次；然后 return。
   2. 否则（自身是源，**或**下方不是「水洞」）→ 只向侧面扩散。
   - 「水洞」= 下方能穿过，且下方已是同种流体或能容纳水（即“水能往下走”）。
4. 向侧面扩散（`spreadToSides`）：以「自身水量 − 1」为传播水量（处于下落状态时固定按 7 计）；只有传播水量 > 0 才扩散。
5. 侧向方向的选择（`getSpread` / `getSlopeDistance`）：
   - 对四个水平方向，能穿过的方向才参与；
   - 若该方向的下一格紧邻一个「水洞」，距离记为 0（**直接优先**）；
   - 否则以该方向为起点**向外递归搜索**，最多 4 格（水的 `getSlopeFindDistance = 4`），取能到达水洞的最短路径长度；
   - 只保留**距离最小**的那些方向（并列则全部保留），且还要满足「新水能替换该处旧流体」和「该处能容纳水」。
7. 落子（`spreadTo`）：目标是含水方块/炼药锅一类的 `LiquidBlockContainer` → 调用 `placeLiquid`（只置 `WATERLOGGED`，不改方块）；
   否则若目标不是空气，先按方块掉落规则破坏它（`beforeDestroyingBlock`），再 `setBlockAndUpdate(流体对应的 water 方块状态)`。

> 水的流动方向向量（`getFlow`）另有一套计算，只影响实体被推动的方向与贴图流动方向，不影响扩散判定。





## 三、一格水的水流向方向向量计算

1. **准备两个累加器**:一个加水平方向：一个记录**东西**方向的倾向，一个记录**南北**方向的倾向，初始都是 0；上下方向一开始也是 0。

2. **计算邻居的高度差并累加**
- **邻居有水**：高度差 = **自己的水面高度 − 邻居的水面高度**。
- **邻居是空气**，且同时满足两个条件：
  1. 那一格不是会挡住水的方块
  2. 那一格的**正下方**也有同一种流体，且水面高度大于 0。

  这时把下方水面高度**减去 8/9**，当成邻居的等效高度，再算高度差：
  **高度差 = 自己的水面高度 −（下方水面高度 − 8/9）**
- **其他情况**：这个方向高度差为 0，不贡献。

高度差不是 0 时，把它乘以该方向的水平方向（东 +1、西 −1、南 +1、北 −1），分别累加到东西、南北两个累加器里。

> 为什么要减 8/9：8/9 正好是一格水的满高度。这一步的效果是——当水在某个方向“旁边是个能掉下去的洞”时，会被强烈地吸向那个方向，也就是**水优先朝有落差、能往下走的地方偏**。
3. **下落水修正**

如果这一格水带**下落标记**`FALLING`：再检查东西南北四个方向，只要任意一个方向（连同自己正上方那一格）存在**实心面**，就在返回时把上下方向的倾向直接设成 **−6**（强烈朝下），然后停止检查。

「实心面」的判定：同种流体不算；朝上的那一面一律算实心；冰不算；其余按方块侧面是否为完整实心面来判断。


4. **归一化，得到最终方向向量**

把累加出的方向向量**归一化**（长度缩成 1）。所以流向计算的输出永远是：

- **单位长度的方向向量** —— 只表示“往哪个方向”，不表示“多强”；
- 或者**零向量**（长度 0，代表没有可参考的水面差，不产生推动）。

强度由使用方向向量的一方决定（贴图流动快慢、物体推动量大小）。

### 6. 这个方向向量被谁用

| 使用者       | 用途                                                             |
| ------------ | ---------------------------------------------------------------- |
| 实体推动逻辑 | 决定水把物体往哪推                                               |
| 画面渲染     | 水面贴图的流动方向、某些面的剔除判断                             |
| 注意         | 它与「水的扩散」无关：流向计算**只读取**周围的水，不改变任何方块 |

## 四、水的响应流程

- **放置水（水桶 / 流体生成）**
  - 目标是可替换的方块或空气 → `setBlock(水的 legacy 方块, flags=11)`；目标是 `LiquidBlockContainer`（含水方块、炼药锅等）→ `placeLiquid`。
  - 之后由 `onPlace` 添加计划 5 gt 流体刻 → 5 gt 后按第三节流程扩散。

- **相邻方块变化**
  - `neighborChanged`：恒添加计划 5 gt。
  - `updateShape`：仅当自身是源或邻居是源时添加计划 5 gt。
  - 于是「挖掉水源下方的方块」会唤醒水源，5 gt 后开始向下/向侧流动。

- **源 → 流动**
  - 源被唤醒后：下方有水洞 → 向下扩散并变成下落水；下方没有水洞 → 向侧面扩散。
  - 侧向每经过一格水量 −1，最多流 7 格（水量 8 → 1）；下落状态不衰减。

- **流动 → 源**
  - 重算时水平源邻居 ≥ 2、下方是实心或水源、且 `WATER_SOURCE_CONVERSION` 开启 → 变成水源（无限水）。
  - 若该规则关闭，则永远不会自发变源。

- **流动 → 空气（回流）**
  - 重算水量 ≤ 0（周围没有更高的同种水）→ 该格变空气，不再重添加计划；其邻居会在各自的刻里继续回退。

- **下落水（`falling = true`）**
  - 上方有同种流体时本格为下落水，水量按 8 处理，可直接补满；落到实心方块上方后转为普通流动水并向侧面铺开。

- **与熔岩相遇（判定发生在熔岩一侧与下落交汇处）**
  - 水从上方流到熔岩上 → 该处变石头；
  - 水出现在熔岩方块旁边 → 熔岩源变黑曜石、流动熔岩变圆石（由熔岩方块的 `shouldSpreadLiquid` 处理）；
  - 水比熔岩高 ≥ 0.444 时允许水替换熔岩。

- **含水方块（`WATERLOGGED`）**
  - 放水 → 方块不变、属性置真；取水 → 属性置假，若此时方块无法存活则连带破坏（掉落）。
  - 含水方块的流体刻与普通水共用同一套扩散逻辑，但 `spreadTo` 走 `placeLiquid` 分支，不会把方块冲掉。

- **结冰 / 积雪**
  - 与流体刻无关：由区块随机刻里的降水处理（每刻 1/48 概率）按生物群系 `shouldFreeze` 把水面变为冰。
