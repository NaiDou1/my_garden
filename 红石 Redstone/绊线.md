# 绊线 Tripwire（未核对）
> 基于26.3snapshot8，正式版可能会调整代码

绊线系统由 **绊线钩（TripWireHookBlock）** 和 **绊线（TripWireBlock）** 组成。两个绊线钩之间可以拉出一条绊线，当实体经过时，钩子会输出红石信号。

---

## 一、方块状态

### 1. 绊线钩

绊线钩有 3 个方块状态：

| 属性       | 类型              | 含义                                       | 默认值            |
| ---------- | ----------------- | ------------------------------------------ | ----------------- |
| `FACING`   | `Direction`       | 水平朝向，指向绊线延伸方向                 | `Direction.NORTH` |
| `POWERED`  | `BooleanProperty` | 是否输出红石信号                           | `false`           |
| `ATTACHED` | `BooleanProperty` | 是否与对端绊线钩形成完整连接并处于绷紧状态 | `false`           |

注意：

- `FACING` 指向线的延伸方向，同时决定强信号输出方向。
- `ATTACHED` 表示两个绊线钩之间至少有一段绊线，且线路未被断开。

---

### 2. 绊线

绊线有 7 个方块状态：

| 属性       | 类型              | 含义                       | 默认值  |
| ---------- | ----------------- | -------------------------- | ------- |
| `POWERED`  | `BooleanProperty` | 是否有实体正在触发该线     | `false` |
| `ATTACHED` | `BooleanProperty` | 是否与两侧绊线钩连接       | `false` |
| `DISARMED` | `BooleanProperty` | 是否被剪刀剪断而失效       | `false` |
| `NORTH`    | `BooleanProperty` | 北方向是否连接绊线或绊线钩 | `false` |
| `EAST`     | `BooleanProperty` | 东方向是否连接绊线或绊线钩 | `false` |
| `SOUTH`    | `BooleanProperty` | 南方向是否连接绊线或绊线钩 | `false` |
| `WEST`     | `BooleanProperty` | 西方向是否连接绊线或绊线钩 | `false` |

注意：

- 四个方向属性只用于连接判断和纹理显示，实际碰撞与触发只取决于 `POWERED` 和 `ATTACHED`。

---

## 二、绊线的放置、连接与触发

### 1. 绊线钩的放置

- 放置时 `getStateForPlacement` 会在水平候选方向中选择一个可以存活的朝向。
- 可以存活的条件是：`FACING` 的反方向紧邻方块必须能够提供实心支撑面。
- 因此绊线钩附着在后方的实心方块上，并朝前方伸出。
- 放置成功后立即执行一次 `calculateState`，计算线路状态。

### 2. 绊线的放置与连接

绊线放置时会设置四个水平方向的连接状态：

- 相邻方块是绊线钩，并且该钩子的 `FACING` 正好朝向这根线；
- 相邻方块是另一段绊线。

具体判断由 `shouldConnectTo` 完成：

- 如果邻居是绊线钩，则要求 `TripWireHookBlock.FACING == direction.getOpposite()`。
- 如果邻居是绊线，则直接连接。

水平邻居发生变化时，`updateShape` 会更新对应方向的连接状态。

### 3. 实体触发

绊线检测实体的入口是 `entityInside`：

- 仅在服务端生效。
- 只有当前 `POWERED == false` 且该线没有已经排队的计划刻时，才会立即检查实体。
- 检查时使用线的碰撞形状选中相交实体。
- 如果至少有一个实体没有忽略方块触发器（`isIgnoringBlockTriggers()`），则判定为触发。

触发后：

- 线的 `POWERED` 被设为 `true`。
- 调用 `updateSource` 通知相应绊线钩重算。
- 安排一个 **10 gt** 后的计划刻，用于后续重新检查。

### 4. 剪刀剪断

当玩家主手拿着剪刀破坏绊线时：

- 线会先被设为 `DISARMED = true`。
- 然后触发剪切事件，再执行正常破坏流程。
- 被剪断的线在钩子重算时不会计入触发，并且如果它是更新源，会直接使钩子 `ATTACHED` 变为 `false`，从而断开整条绊线。

## 三、钩子的状态计算与输出

绊线钩的核心逻辑集中在 `calculateState`。

### 1. 触发时机

以下情况会调用 `calculateState`：

- 绊线钩放置后；
- 绊线被放置、移除或状态变化时，通过 `updateSource` 调用；
- 绊线钩被移除时；
- 绊线钩的计划刻执行时。

### 2. 输入参数

`calculateState` 接收两个与更新源相关的参数：

- `wireSource`：触发计算的绊线到当前钩子的距离；`-1` 表示没有来自绊线的更新源。
- `wireSourceState`：更新源绊线的方块状态。由于该线可能正在被放置或移除，世界上尚未同步，因此用它覆盖世界状态。

### 3. 计算流程

初始化：

- `attached = !isBeingDestroyed`
- `powered = false`
- `receiverPos = 0`，表示对端绊线钩的距离
- 准备一个长度为 42 的数组保存扫描到的绊线状态

沿当前钩子的 `FACING` 方向从 `1` 到 `41` 扫描：

#### 遇到绊线钩

- 停止扫描。
- 如果该钩子的 `FACING` 正好是当前方向的反方向，则记录 `receiverPos = i`。

#### 遇到非绊线方块

如果该位置不是绊线，且不是 `wireSource` 指定位置：

- `attached = false`。

线路被阻断，不再完整。

#### 遇到绊线

读取该绊线状态：

- `wireArmed = !DISARMED`
- `wirePowered = POWERED`
- 累加触发：`powered |= wireArmed && wirePowered`

如果该位置是 `wireSource`：

- 使用传入的 `wireSourceState` 替代世界状态。
- 给当前绊线钩安排一个 **10 gt** 的计划刻。
- 更新 `attached &= wireArmed`。

---

扫描结束后：

```java
attached &= receiverPos > 1;
powered &= attached;
```

解释：

- `receiverPos > 1`：两个绊线钩之间至少要有 1 段绊线，两个钩子直接相邻不算连接。
- `powered &= attached`：只有线路完整连接时，线上触发才会使钩子输出信号。

然后生成新状态：

- 本方绊线钩：`FACING` 不变，更新 `ATTACHED` 和 `POWERED`。
- 如果找到对端钩子，则同步更新对端钩子，并通知邻居。
- 如果 `ATTACHED` 发生变化，则遍历两个钩子之间的绊线，同步更新它们的 `ATTACHED`。

---

### 4. 红石输出

当绊线钩 `POWERED == true` 时：

- `ownSignal` 返回 `15`。
- `getDirectSignal` 只对 `FACING` 方向返回 `15`，其他方向返回 `0`。

也就是说，绊线钩被触发后：

- 它对自己的 `FACING` 方向提供强充能。

## 四、绊线系统如何添加计划刻

### 1. 绊线添加计划刻

- 实体进入后，如果 `POWERED` 从 `false` 变为 `true`，线会安排一个 **10 gt** 的计划刻。
- 之后每 10 gt 重新检查一次：
  - 如果实体仍在，继续安排 10 gt；
  - 如果实体离开，`POWERED` 变为 `false`，
  - 
>  并安排一个 **0 gt** 的计划刻?(不知道是否会被修掉)

### 2. 绊线钩添加计划刻

- 在 `calculateState` 扫描线路时，如果遇到 `wireSource` 指向的那根绊线，会为当前绊线钩安排一个 **10 gt** 的计划刻。
- 该机制用于在绊线被放置、移除或状态变化后延迟重算，避免在同一游戏刻内反复更新。

---

## 五、绊线系统执行计划刻时

### 1. 绊线执行计划刻

绊线的 `tick` 逻辑：

- 只有当前线方块状态为 `POWERED == true` 时，才会再次执行 `checkPressed`。
- `checkPressed` 会重新获取碰撞形状内的实体列表。
- 如果判定结果与当前状态不同：
  - 更新 `POWERED`；
  - 调用 `updateSource` 通知相关绊线钩。
- 如果仍然应该保持触发，继续安排 10 gt 计划刻。
- 如果刚刚关闭且旧状态为触发，会安排一个 0 gt 计划刻；下一次 tick 时由于 `POWERED` 已经为 `false`，不再重复检查。

### 2. 绊线钩执行计划刻

绊线钩的 `tick` 会执行一次：

```java
calculateState(level, pos, state, false, true, -1, null);
```

也就是：

- 重新扫描线路；
- 更新 `ATTACHED` 和 `POWERED`；
- 同步对端绊线钩以及中间绊线的状态；
- 根据状态变化输出红石信号或播放声音。
